TCC-CORE REAL ROBOT - LINUX COMMANDS
====================================

Purpose
-------
This file is the single source of copy/paste commands for the Linux robot PC.
Update it in Git whenever the next command changes. Do not copy commands through
WeChat, because its web client may replace line breaks with escaped <br> text.


0. UPDATE THIS FILE FROM GITHUB
-------------------------------

cd /home/robotarm/tcc-core-real-robot
git pull
less LINUX_COMMANDS.txt


1. ENTER THE PROJECT ENVIRONMENT
--------------------------------

cd /home/robotarm/tcc-core-real-robot
source .venv/bin/activate


2. INSTALL OR UPDATE PROJECT DEPENDENCIES
-----------------------------------------

python -m pip install --upgrade pip
python -m pip install -e '.[train,eval,robot,dev]'

The train extra installs the av package required for reading dataset videos.
Verify it with:

python -c "import av; print(av.__version__)"


3. DOWNLOAD THE PINNED DATASET
------------------------------

cd /home/robotarm/tcc-core-real-robot
hf download UoA-Trossen-Arm/pick_and_place_4_object_diverse --repo-type dataset --revision 6ce893dc73fc6310ccbd46786f71a03a5b6a3da2 --local-dir datasets/pick_and_place_4_object_diverse

Verify the dataset directory:

test -d datasets/pick_and_place_4_object_diverse && echo DATASET_OK


4. DOWNLOAD AND VERIFY THE PINNED MODEL
---------------------------------------

python scripts/fetch_policy_assets.py --backbone ours_rn50 --demonstrations 60

Verify the cached model without network access:

python scripts/fetch_policy_assets.py --backbone ours_rn50 --demonstrations 60 --offline


5. CHECK THE CAMERAS
--------------------

ls -l /dev/v4l/by-id/
python scripts/preview_cameras.py

For a Linux PC without a graphical desktop:

python scripts/preview_cameras.py --no-display

Preferred mapping, which must be checked again after a reboot or USB reconnect:

cam_main  = /dev/video10
cam_wrist = /dev/video2
fallback  = /dev/video4

/dev/video2 has failed intermittently and later recovered. Prefer it when it
returns a 480x640x3 color frame because its color is closer to the demo input.
Use /dev/video4 only as a temporary fallback; its green color cast is a possible
policy domain shift and must be noted when reviewing predictions.

If an evaluation reports "Failed to grab a synchronized camera pair", check
that both nodes still exist and that no preview or Python process owns them:

ls -l /dev/video2 /dev/video4 /dev/video10
fuser -v /dev/video2 /dev/video4 /dev/video10

COPY-SAFE SINGLE-LINE DEVICE CHECK

Use this exact one-line command when copying through a web page. The semicolons
prevent adjacent commands from being joined together:

ls -l /dev/video*; if test -e /dev/video2; then echo VIDEO2_EXISTS; else echo VIDEO2_MISSING; fi; if test -e /dev/video4; then echo VIDEO4_EXISTS; else echo VIDEO4_MISSING; fi

Check whether the persistent D405 links resolve to real device nodes:

readlink -e /dev/v4l/by-id/*405*video-index2; readlink -e /dev/v4l/by-id/*405*video-index4

Interpretation:

- A printed /dev/video path means that persistent link is valid.
- No output from readlink means the by-id link is dangling.
- Do not run policy evaluation while both D405 color nodes are missing or fail
  to return frames.

If fuser prints a PID, inspect it before stopping it:

ps -fp PID

Replace PID with the displayed process number. Stop only a confirmed stale
camera process owned by the current user:

kill PID

Then probe the cameras again and rerun the shadow test:

python scripts/preview_cameras.py --no-display


6. RUN THE DEMO FIRST-FRAME OFFLINE DIAGNOSTIC
----------------------------------------------

This command does not connect to or move the robot.

python scripts/eval_demo_first_frames.py --backbone ours_rn50 --demonstrations 60 --task carrot --episodes 10 --tcc-source-root /home/robotarm/TCC-core --offline --device auto

Review the newest report:

less "$(ls -t outputs/demo_first_frames_*.txt | head -n 1)"

If the decision is BLOCKED, do not proceed to real policy actuation.


6A. OPTIONAL CAMERA-ONLY SHADOW TEST WHILE THE DATASET DOWNLOADS
---------------------------------------------------------------

Open a second terminal, activate the same environment, and run this command.
It reads the cameras and computes policy predictions, but it does not connect to
or move the robot because --execute-home and --execute are both omitted.

cd /home/robotarm/tcc-core-real-robot
source .venv/bin/activate
python scripts/run_policy.py --backbone ours_rn50 --demonstrations 60 --task carrot --cam-main /dev/video10 --cam-wrist /dev/video2 --tcc-source-root /home/robotarm/TCC-core --offline --device auto --max-steps 10

The simultaneous download can reduce the measured inference rate, so use this
only as an input/model smoke test. Do not treat its timing result as final.


7. RUN A 10-STEP SHADOW EVALUATION
----------------------------------

This stages the robot at dataset_collection_home and holds that pose. Policy
predictions are recorded but are not sent to the robot.

python scripts/run_policy.py --backbone ours_rn50 --demonstrations 60 --task carrot --cam-main /dev/video10 --cam-wrist /dev/video2 --tcc-source-root /home/robotarm/TCC-core --offline --device auto --execute-home --max-steps 10

Review the newest report:

less "$(ls -t outputs/policy_shadow_*.txt | head -n 1)"


8. RUN A 359-STEP SHADOW EVALUATION
-----------------------------------

Only run this after the 10-step report passes all checks.

python scripts/run_policy.py --backbone ours_rn50 --demonstrations 60 --task carrot --cam-main /dev/video10 --cam-wrist /dev/video2 --tcc-source-root /home/robotarm/TCC-core --offline --device auto --execute-home --max-steps 359


9. REVIEW OUTPUT FILES
----------------------

ls -lt outputs/*.txt | head -n 20
python scripts/check_output_reports.py


10. RETURN THE ROBOT TO IDLE OR THE FOLDED POSE
----------------------------------------------

The evaluation program restores Idle when it exits normally or is interrupted.
To return from dataset_collection_home to the recorded folded pose:

python scripts/return_to_folded_pose.py --execute


11. SYNC REPORTS TO GITHUB
--------------------------

Review the exact files before committing:

git status --short
git diff -- outputs/

Then add only the intended TXT reports, commit, and push. Replace REPORT_FILE.txt
with the actual filename:

git add outputs/REPORT_FILE.txt
git commit -m "Add robot evaluation report"
git push


SAFETY STATUS
-------------

Policy execution is still disabled. Do not add --execute to run_policy.py.
The --execute-home option only moves to dataset_collection_home; it does not
execute predicted policy actions. A BLOCKED or FAIL report must be investigated
before any real-action evaluation is implemented.
